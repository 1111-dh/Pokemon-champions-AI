# 엔진 미모델링 항목

엔진(Showdown champions 모드)이 게임과 다르게 처리하거나 아직 구현하지 않은 효과를 기록한다.
항목마다 근거(게임 관찰, 출처)와 영향 범위, 대응을 적는다.

| 항목 | 내용 | 근거 | 영향 | 대응 |
|---|---|---|---|---|
| 세트 원형의 결합 정보 | 완성 세트가 없어 도구×기술 조합은 규칙 필터와 IPF로 추정한다. 성격·배분은 원형의 물리/특수 성향으로만 조건을 건다 (도구별 배분 차이는 반영 못 함) | `docs/VERIFIED.md` 세트 원형 | 믿음 상태 사전확률, 선출 행렬의 상대 세트 | 완성 세트 출처(대회 팀, 사용자 입력 팀)를 확보하면 team_samples로 넣는다 |
| `/damage`의 상황 의존 효과 | 변환자재·리베로(첫 기술의 타입 변경), 애널라이즈(나중에 행동), 메타몽 괴짜(등장 시 변신)는 1:1 데미지 조회에 반영하지 않거나 엔진의 기본 가정을 따른다. 연속기는 첫 타 데미지만 낸다 | `engine/scripts/damage-crosscheck.ts` | 해당 특성·기술의 데미지 우도 | 믿음 상태(9.2)에서 이 경우는 /step 시뮬레이션 결과를 쓰거나 허용 오차를 넓힌다 |
| 12월 2일 배틀 밸런스 조정 | 기술 습득 추가, 기술 5개 명중률 등, 특성 2개 변경 (VERIFIED.md 참고) | 공식 공지 877 | 해당 기술·특성을 쓰는 데미지, 명중, 세트 후보 | 12월 2일 이후 Showdown 서브모듈 갱신 여부를 확인하고, 반영 전까지는 이 항목을 쓰는 추천에 표시 |
| 빠른 상성 근사의 한계 | 변화기(칼춤, 나쁜음모, 대타출동, 방어, 기술로 까는 날씨·필드, 트릭룸, 벽, 순풍, 스텔스록 등), 교체, 상태이상 부가효과, 날씨·필드를 바꾸는 기술은 HP 경주에 넣지 않는다. 그래서 랭크업 기술이나 대타출동을 쓰는 세트는 낮게 평가될 수 있다 | `docs/VERIFIED.md` 1:1 상성 | 파티 추천의 후보 비교, 선출 행렬의 근사값 칸 | 선출(단계 4)은 핵심 칸을 정밀 시뮬레이션하고, 기술 선택(단계 5)은 탐색으로 다룬다 |
| 빠른 상성 근사의 날씨·필드 (v3 이후 남은 것) | v3에서 지속 턴, 날씨 스피드·명중·회복 특성, 그래스필드·사이코필드 효과를 넣었다(`VERIFIED.md`). 남은 것: 일렉트릭필드·미스트필드의 상태이상 방지(근사가 상태이상을 다루지 않음, M-C에 미스트필드를 까는 특성 없음), 리프가드·촉촉바디(상태이상), 수확(쾌청에서 열매 재사용), 풍선이 맞으면 터지는 것(근사와 @smogon/calc 모두 계속 든 것으로 봄), 메가진화로 까는 날씨의 시작 시점(근사는 첫 턴 시작부터 메가 폼) | `engine/src/matchup.ts` | 해당 특성·도구를 쓰는 세트의 1:1 근사값 | 상태이상과 풍선은 정밀 시뮬레이션(단계 4 3:3)과 탐색(단계 5)이 다룬다. 수확은 사례가 문제 되면 넣는다 |
| 빠른 상성 근사의 상대 능력 하락 | v3에서 확정 부가효과의 공격·특공·스피드 하락은 넣었다. 방어·특방 하락(애시드봄, 루미나콜리전 등)과 확률 부가효과(풀죽음, 상태이상, 능력 하락)는 넣지 않는다 | `engine/src/matchup.ts` | 해당 기술을 쓰는 세트의 1:1 근사값 | 정밀 시뮬레이션과 탐색이 다룬다 |
| 배틀 입력: 일루전 | 조로아크(일루전)가 다른 포켓몬으로 보이는 동안의 사건은 겉보기 포켓몬에 붙는다. 일루전이 풀리면(일루전 해제 입력) 실제 포켓몬으로 바꾸지만 그 전 기록은 고치지 않는다 | `pokechamp battle-check` (100판 중 4판) | 일루전 판의 상태 추적, 믿음 상태 | 믿음 상태(단계 5)에서 '이 포켓몬이 조로아크일 확률'을 두는 방식으로 다룬다 |
| 배틀 입력: LLM 보조 | 규칙 파서가 해석하지 못한 문장을 LLM으로 구조화하는 경로는 아직 없다(해석 실패는 오류로 돌려주고 다시 입력받는다) | PROJECT_PLAN 9.1 | 형식에서 벗어난 입력 | battle 세션 단계에서 API 키 설정과 함께 넣는다 (스키마 검증 필수) |
| 선출 추천의 정밀 칸 | 정밀 칸은 최대 데미지 봇의 3:3 시뮬레이션이다. 봇이 스스로 교체하지 않고 변화기를 쓰지 않으며, 앞 포켓몬이 쓰러진 뒤 나올 포켓몬을 무작위로 고른다. 그래서 '선봉'은 첫 자리만 뜻하고, 뒤 두 마리의 순서·교체 운용은 평가하지 않는다. 칸당 16판이라 칸 하나의 표준오차가 약 0.1이다 | `agent/pokechamp/select/` | 선출 확률과 예상 승률 | 단계 5 탐색 에이전트를 시뮬레이션 정책으로 쓰면 다시 잰다. 엔진 병렬화(단계 7)로 칸당 판 수를 늘린다 |
| 선출 추천의 상대 모델 | 통계 출처가 선출률·선봉률을 주지 않아, 상대 선출 분포를 '사용률 × 상대 입장에서 유리한 선출' 가정으로 둔다 (온도 5, 섞는 비율 0.3) | 통계 출처(championsbattledata)는 사용률 순위만 제공 | 최종 확률의 30%(상대 모델 최선 응수) | 단계 6에서 내 배틀 기록과 공개 리플레이로 학습한다 |
| 선출 추천의 메가 순서 근사 | 근사 행렬은 선출 안에서 출전 순서상 첫 소지자가 메가진화한다고 본다(선봉이 아니면 슬롯 순서). 실제 봇은 먼저 나온 소지자로 메가진화하므로 뒤 두 마리 중 누가 먼저 나오는지에 따라 다를 수 있다 | `select/picks.py` | 상대가 소지자를 둘 이상 낸 선출의 근사값 | 정밀 칸(엔진)은 실제 순서대로 처리하므로 후보 칸에는 영향 없음 |
| 팀 단위 날씨·필드 연계 | 빠른 근사와 팀 점수는 1:1 상성의 조합이라 선출 안의 연계(날씨를 까는 포켓몬 + 그 날씨에서 강해지는 파트너)를 직접 평가하지 못한다. 단계 4에서 선출의 정밀 칸과 파티 추천 빔 상위 6팀 재평가를 3:3 시뮬레이션으로 해서, 그 칸·후보에서는 앞 포켓몬이 깐 날씨가 이어지는 효과가 반영된다. 빔에 들어오기 전 단계(근사 점수)에서 걸러진 날씨 팀은 여전히 놓칠 수 있다 | 사용자 지적(2026-11-19) | 날씨·필드 팀의 파티 추천 후보 생성 | 빔 폭·재평가 후보 수를 늘리거나, 단계 7에서 엔진 병렬화로 더 많은 후보를 3:3으로 본다 |
| 파티 추천 검증의 봇 | 검증 시뮬레이션은 양쪽 모두 최대 데미지 봇이고 선출은 무작위다. 변화기를 쓰지 않는 봇이라 변화기 중심 팀의 실제 강함과 다를 수 있다 | `docs/VERIFIED.md` 파티 추천 | 추천 팀 승률 수치 | 단계 4~5의 선출·기술 선택 에이전트가 생기면 같은 검증을 그 정책으로 다시 돌린다 |

단계 1에서 허용 목록의 기술과 특성을 엔진 구현과 대조해 이 표를 채운다.
