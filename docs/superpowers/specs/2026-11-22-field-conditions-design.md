# 실전 탭: 벽 · 순풍 · 트릭룸 · 설치기 설계

## 의도
실전 탭에서 벽·필드 같은 배틀 상태를 한눈에 보이게 한다. 표시만 붙이면 "벽은 보이는데 추천은 벽을 무시하는" 상태가 되므로,
**추적 → 계산(기술 추천·예상 HP) → 표시**를 함께 한다. 사용자 선택: 범위 3번(벽 + 순풍·트릭룸 + 설치기).

## 지금 상태
- 날씨·필드: `BattleState.weather/terrain`(Clock: 끝나는 턴 하한·상한)으로 추적, 실전 화면에 글자 한 줄, 탐색(`/build_state` field)에 남은 턴 전달.
- 벽·순풍·트릭룸·설치기: 추적·표시·계산 모두 없음. 실전 탭 교체 때 설치기 데미지 없음.

## 범위
| 종류 | 대상 | 규칙 (엔진 data/moves.ts, 챔피언스는 바꾸지 않음) |
|---|---|---|
| 벽 | 리플렉터, 빛의장막, 오로라베일 | 5턴, 빛의점토 8턴. 같은 벽이 있으면 실패 |
| 순풍 | 순풍 | 4턴 |
| 트릭룸 | 트릭룸 (양쪽 공통) | 5턴, 켜진 상태에서 다시 쓰면 끝남 |
| 설치기 | 스텔스록, 압정뿌리기(최대 3겹), 독압정(최대 2겹), 끈적끈적네트 | 지울 때까지 남음. 상대 쪽에 깔린다 |

지우는 기술: 깨트리기·사이코팽·분노의황소(맞는 쪽 벽), 고속스핀·대회전(자기 쪽 설치기), 안개제거(맞는 쪽 벽·설치기 + 자기 쪽 설치기),
정리정돈(양쪽 설치기), 코트체인지(양쪽 벽·순풍·설치기 맞바꿈). 정확한 대상 목록은 엔진 코드를 따른다.

## 하지 않는 것
- 신비의부적·하얀안개 등 다른 사이드 조건, 기술 외 원인(매직미러 반사 등)의 자동 처리 — 화면에서 직접 켜고 끈다.
- 빛의점토 증거로 상대 도구 믿음 갱신(벽이 5턴을 넘으면 빛의점토) — 다음에.
- 계산기 탭 변경.

## 설계
### 추적 (`battle/state.py`, `battle/events.py`)
- 사건 종류 추가: `sidestart`/`sideend`(side, value=조건 id), `room`(value="trickroom" | "none").
- `Side.conds`: 조건 id → 상태. 벽·순풍은 Clock(끝나는 턴 하한·상한), 설치기는 겹 수.
- `BattleState.trickroom`: Clock.
- 시계 규칙은 날씨와 같다(`end_turn`): 내 벽은 내 도구로 5/8 확정, 상대 벽은 도구를 모르면 5~8, 다른 도구가 드러나면 5.
- 시계가 다 되면(턴 끝) 자동으로 꺼진다. 날씨와 같은 위치에서 처리한다.
- `LogConverter`: Showdown 로그의 `-sidestart`/`-sideend`/`-fieldstart|-fieldend Trick Room` → 위 사건. 자동 대전(검증)도 같은 추적을 탄다.

### 실전 입력 (`battle/live.py`)
- 사용자가 넣은 기술(내·상대)에서 위 표대로 sidestart/sideend/room 사건을 만들어 기술 사건 뒤에 넣는다.
- 빠뜨린 경우를 위해 직접 켜고 끄는 API: `POST /api/live/field` {side: me|opp|field, cond, on: bool, layers?}.

### 계산
- 탐색: `/build_state`에 `sideConditions: {p1: {id: 남은 턴 | 겹 수}, p2: …}`, `trickRoom: 남은 턴`을 더한다. 남은 턴은 하한(날씨와 같음).
  엔진이 그 상태로 롤아웃하므로 벽(데미지), 순풍·트릭룸(행동 순서), 설치기(교체 데미지)가 추천에 들어간다.
- 예상 HP(`estimate`): 맞는 쪽 벽을 `/damage` field.screens로 넣는다.
- 교체 등장: 설치기가 있는 쪽에 포켓몬이 나오면 엔진에 등장 효과를 계산시켜(데미지, 독·맹독, 끈적끈적네트 스피드 −1) 위협처럼 자동 적용한다.
  상대 포켓몬은 믿음 상위 세트(특성·도구: 부유, 풍선 등)로 계산한다. 새 엔진 API `/entry_hazards` {set, mega, hazards} → {damage, status, boosts}.

### 화면 (`web/static`)
- 실전 화면 위쪽에 '필드 막대': 왼쪽 내 쪽 조건, 가운데 날씨·필드·트릭룸, 오른쪽 상대 쪽 조건. 각 칩에 남은 턴(상대는 범위)이나 겹 수.
- 칩을 누르면 끄기(확인), [+ 추가]로 직접 켜기(종류·쪽 선택).
- 지금의 '날씨 … · 필드 …' 한 줄은 이 막대로 바꾼다.

### 믿음 상태 (`battle/session.py`, `battle/belief.py`) — 리뷰 후 추가, Claude가 정함
- 행동 순서 증거(`observe_order`): 순풍은 그 쪽 스피드 ×2, 트릭룸은 느린 쪽이 먼저(비교 방향 반전). 엔진 규칙 그대로.
  반영하지 않으면 트릭룸·순풍 아래에서 맞는 파티클이 지워지고, 가중치가 모두 0이 되어 "입력 오류" 확인까지 갈 수 있다.
- 데미지 증거(`observe_damage`): 맞는 쪽의 벽을 field.screens로 넣는다. 빼면 벽으로 줄어든 데미지를 상대 내구의 증거로 잘못 쓴다.
- 설치기 등장 데미지(자동값)는 믿음 증거로 쓰지 않는다. 챔피언스에는 두꺼운부츠가 없어(허용 도구 목록) 불확실한 것은
  부유·풍선·매직가드 정도이고, 엔진이 믿음 상위 세트로 계산한다. 턴 요약에 보여 주고 사용자가 HP 칸에서 고칠 수 있다.

### 직접 켜기 — 리뷰 후 추가, Claude가 정함
- `POST /api/live/field` {side, cond, on, turns?, layers?}. [+ 추가] 화면에 남은 턴 칸(기본값 = 처음 지속 시간: 벽 5, 순풍 4, 트릭룸 5).

## 테스트
- 추적: 리플렉터 사용 → 5턴 뒤 꺼짐, 빛의점토 8턴, 상대 5~8, 같은 벽 재사용 무시, 트릭룸 재사용 끝, 압정 3겹 상한, 지우는 기술별 결과, 코트체인지 교환.
- LogConverter: Showdown 로그 줄 → 사건.
- 엔진: `/build_state` 조건 반영(남은 턴), `/entry_hazards`(스텔스록 상성 배율, 부유는 압정 면제, 독압정 2겹 맹독, 독 타입은 독압정 흡수).
- 실전: 기술 입력 → 필드 막대 데이터, 교체 시 설치기 데미지 자동, 예상 HP에 벽.
- 믿음: 트릭룸·순풍 아래 행동 순서 증거가 맞는 파티클을 지우지 않는다, 벽이 있을 때 데미지 증거가 벽을 넣는다.
- 기존 자동 대전 검증(에이전트 대 봇)이 오류 없이 돈다.
